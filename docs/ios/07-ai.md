# AI-функции на клиенте

Серверная сторона — [../07-ai-drafts.md](../07-ai-drafts.md), [../08-ai-continuations.md](../08-ai-continuations.md), доступ — [../11-plans-and-features.md](../11-plans-and-features.md).

## Доступ к AI-функциям и согласие

AI-функции есть не у всех пользователей. Источник — профиль (`GET /v1/me`, `entity_type: user` в sync и snapshot):

```json
{ "features": ["ai_continuations", "ai_drafts", "ai_import"], "ai_consent_at": "2026-10-18T09:00:00Z" }
```

| Ключ | Функция |
|---|---|
| `ai_drafts` | голосовые AI-черновики |
| `ai_continuations` | «Продолжение нити» |
| `ai_import` | импорт файлов других приложений ([08](08-export-import.md#файл-другого-приложения--через-ai)) |

Неизвестные ключи игнорировать; нет поля `features` (старый сервер) — считать `[]`.

### Функции нет в `features`

- Точка входа **не показывается вовсе**: без замков, бейджей, «скоро», упоминаний Nodus+, подписки или тестирования.
  - нет `ai_drafts` — нет кнопки диктовки / AI-ввода; раздел «Черновики» показывается, только если в нём есть незавершённые задания;
  - нет `ai_continuations` — в UI ничего не меняется; уже пришедшие предложения показываются как обычно;
  - нет `ai_import` — экран импорта говорит только о файлах Nodus.
- Начатое не ломается: задания черновиков и импорта (`queued`/`processing`/`ready`) видны, их можно подтвердить или отменить; предложения можно принять.
- Функция появилась в `features` (sync/SSE) — точка входа появляется сразу, без перезапуска; исчезла — скрывается.

### Согласие

Источник истины — `ai_consent_at` с сервера, не локальный флаг: без согласия сервер не отправит данные модели (App Review Guideline 5.1.2(i)).

- `features` не пуст, а `ai_consent_at = null` → при первой попытке открыть AI-функцию (диктовка, импорт чужого файла) показать экран: какие данные и кому отправляются, зачем, ссылка на privacy policy; кнопки «Разрешить» / «Не сейчас».
- «Разрешить» → через Outbox `PUT /v1/me/ai-consent { "granted": true }` → `200 UserProfile`; затем запустить функцию. «Не сейчас» → не запускать, спросить при следующей попытке.
- Если из AI-функций есть только `ai_continuations` (нет явной точки входа) — один раз ненавязчиво предложить экран согласия, например после создания первого одноразового узла; отказ запомнить локально и больше не спрашивать.
- Настройки: переключатель «AI-помощник» (виден, только если `features` не пуст) с текстом о передаче данных. Выключение → `PUT /v1/me/ai-consent { "granted": false }`.
- Повтор `granted: true` безопасен: время первого согласия и `version` не меняются.

### Ошибки доступа

| Ответ | Действие |
|---|---|
| `403 feature_not_available` (`feature` — ключ) | операция `failed`, **не повторять**; `GET /v1/me`, обновить `features`, скрыть точку входа; нейтрально: «Эта функция сейчас недоступна» |
| `403 ai_consent_required` (`feature`) | операция `failed`, не повторять автоматически; обновить профиль, показать экран согласия; после «Разрешить» — новая операция с новым ключом |

Для `POST /ai/node-drafts` отказ не сохраняется за ключом, для `POST /me/import` — сохраняется. Клиенту это не важно: после отказа всегда новая операция с новым ключом.

### App Review

В App Review Notes: AI-функции (голосовые черновики, предложения следующего шага, AI-импорт) включены на сервере для ограниченной группы тестирования, доступ выдаётся вручную и бесплатно, покупок вне приложения нет; данные демо-аккаунта с включёнными функциями — в Sign-In Information.

Ревьюер входит через «Настройки → Восстановить аккаунт» (`/v1/auth/email/sign-in/*`): email демо-аккаунта и фиксированный код из Sign-In Information, письмо не приходит. Для клиента это обычный вход — никакой особой логики не нужно; важно, чтобы путь к «Восстановить аккаунт» был описан в Review Notes. Подготовка на сервере — [../02-authentication.md](../02-authentication.md#демо-аккаунт-для-app-review).

## Голосовые AI-черновики

### Поток экранов

1. **Диктовка** — Speech Framework (по возможности on-device), частичный текст на экране, можно поправить перед отправкой. Разрешения на микрофон и распознавание — с объяснением.
2. **Отправка** (только онлайн):
   ```http
   POST /v1/ai/node-drafts      (Idempotency-Key)
   { "text": "…", "timezone": "<IANA>", "reference_time": "<момент диктовки, UTC>" }
   → 202 { "id": "…", "status": "queued", … }
   ```
   `reference_time` — когда пользователь говорил (чтобы «завтра» считалось от этого момента). Текст ≤ 4000 символов.
3. **Ожидание** — анимация «Распутываем мысли…». **Только после `202`** показать «Можно закрыть экран — сообщим, когда будет готово».
4. **Готово** — задание приходит в sync (`ai_draft_job`) / по SSE; если экран открыт — открыть проверку автоматически; если нет — push `ai_drafts_ready` с `job_id` ведёт на **тот же** экран.
5. **Проверка** — список черновиков, каждый редактируется как форма создания узла.
6. **Подтверждение** — одним запросом (рекомендуется):
   ```http
   POST /v1/ai/node-drafts/{jobId}/confirm      (Idempotency-Key)
   { "nodes": [ { "id": "<новый UUID>", "type": "one_time", "title": "…", "timezone": "…", "date": "…", "time": "…" } ] }
   → 200 { "job": {…, "status": "confirmed"}, "created": { "nodes": [ …NodeDto… ] } }
   ```
   Узлы создаются и задание подтверждается атомарно. Локально: создать узлы + операцию confirm в одной транзакции (Outbox). Ошибка валидации любого узла (`400`) — ничего не создано, задание остаётся `ready`.

Раздел **«Черновики»** — `GET /v1/ai/node-drafts` (или локальные `ai_draft_job` со статусами `queued`/`processing`/`ready`): результат доступен, даже если push не пришёл. Отмена — `POST …/{jobId}/cancel`.

### Черновик

```json
{ "index": 0, "type": "one_time", "title": "Позвонить врачу", "description": null, "timezone": "Europe/Moscow",
  "date": null, "time": null, "recurrence": null, "track_years": null,
  "issues": [ { "code": "time_without_date", "field": "date", "message": "…" },
              { "code": "ambiguous", "field": null, "message": "Не ясно, какой день" } ] }
```

Подсветить поле из `issues[].field`, показать сообщение; `field: null` — общее замечание к черновику.

| `issues[].code` | UI |
|---|---|
| `ambiguous` | предупреждение с текстом модели |
| `missing_date`, `time_without_date`, `invalid_date`, `invalid_time` | подсветить дату/время, попросить уточнить |
| `missing_recurrence`, `invalid_recurrence` | подсветить повторение (черновик стал одноразовым) |
| `past_date` | «Дата уже прошла» |
| `needs_review` | нельзя подтвердить, пока не заполнено обязательное |

### Ошибки

| Ситуация | UI |
|---|---|
| нет сети до `202` | сохранить текст локально как черновик, предложить отправить позже |
| `429 ai_quota_exceeded` | «Лимит AI на сегодня исчерпан» (50 в сутки) |
| `403 feature_not_available` / `403 ai_consent_required` | см. [Ошибки доступа](#ошибки-доступа) |
| `status: failed`, `error: ai_unavailable` / `ai_temporarily_unavailable` / `invalid_ai_response` | «Не получилось разобрать» → «Повторить» (новое задание с сохранённым локально текстом — сервер текст не возвращает) или «Создать вручную» |
| `error: nothing_recognized` | «Не нашли дел в записи» |
| `status: expired` (14 дней) | «Черновики устарели», без фиктивных узлов |

Текст диктовки хранить локально до подтверждения или отмены — он нужен для повтора.

## Продолжение нити

Предложения готовятся сервером заранее и приходят через sync (`entity_type: suggestion`):

```json
{ "id": "…", "source_node_id": "…", "status": "ready", "title": "Визит к врачу", "description": null,
  "shown_at": null, "accepted_at": null, "dismissed_at": null, "linked_node_id": null, "version": 1 }
```

Хранить локально (`LocalSuggestions`), индекс по `source_node_id`.

### Когда показывать

При развязывании **одноразового** узла:

- показать карточку **сразу**, только если в момент развязывания локально уже есть предложение `status = ready` и `shown_at = null`;
- в той же транзакции, что и развязывание, отметить показ локально и поставить в Outbox `POST /v1/suggestions/{id}/shown`;
- нет готового предложения — ничего не показывать и не ждать; если оно придёт позже (в том числе после офлайн-развязывания) — **не показывать**;
- после перевязывания и повторного развязывания — не показывать снова.

### Действия на карточке

- **«Завязать»** — открыть форму создания с предзаполненным названием (дату не придумывать). После сохранения — **одна** операция:
  ```http
  POST /v1/suggestions/{id}/accept      (Idempotency-Key)
  { "node": { "id": "<новый UUID>", "type": "one_time", "title": "Визит к врачу", "timezone": "…" } }
  → 200 { "suggestion": {…, "status": "accepted", "linked_node_id": "…"}, "node": { …NodeDto… } }
  ```
  Не делать отдельно «создать узел» и «принять». Связь нового узла с исходным — в предложении (`source_node_id` → `linked_node_id`). `409 already_accepted` — уже принято (с `linked_node_id`).
- **«Не сейчас»** — `POST /v1/suggestions/{id}/dismiss` (Outbox).

Предложение, пришедшее как `delete` (узел изменили по смыслу или удалили), — удалить локально.
