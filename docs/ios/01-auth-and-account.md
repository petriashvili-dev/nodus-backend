# Авторизация и аккаунт

Подробности серверной стороны — [../02-authentication.md](../02-authentication.md).

## Первый запуск

1. Приложение работает сразу, без регистрации; все данные — локально.
2. При первой возможности сети (до первой отправки Outbox) — `POST /v1/auth/anonymous` (без тела). Ответ `201`:
   ```json
   { "user_id": "…", "access_token": "…", "access_token_expires_at": "…",
     "refresh_token": "…", "refresh_token_expires_at": "…", "token_type": "Bearer" }
   ```
3. Сохранить в **Keychain**: `user_id`, оба токена и сроки.
4. Зарегистрировать устройство ([ниже](#устройство-и-apns-токен)) и отправить часовой пояс ([ниже](#часовой-пояс)).
5. Snapshot: `GET /v1/sync/snapshot` → дальше Delta Sync ([03](03-sync-engine.md)).

Если запрос `anonymous` не дошёл — повторить; лишний анонимный аккаунт безвреден.

## Токены

| | Срок | Где |
|---|---|---|
| access | 15 мин | Keychain, в памяти для запросов |
| refresh | 60 дней, продлевается при каждом обновлении | только Keychain |

**Обновление** — `POST /v1/auth/refresh { "refresh_token": "…" }` → новая пара (оба токена новые, старый refresh больше не использовать).

Обязательно:

- **Single-flight:** одновременно выполняется не больше одного refresh; остальные запросы ждут его результата. Повторное использование старого refresh-токена позже чем через 2 минуты сервер считает кражей и **отзывает сессию**.
- Обновлять заранее (за ~1 мин до `access_token_expires_at`) или по `401 unauthorized`, затем повторить исходный запрос **с тем же** `Idempotency-Key`.
- Новую пару записать в Keychain **до** того, как использовать.
- Если ответ на refresh потерялся — повторить со старым токеном можно в течение 2 минут.

`401 invalid_refresh_token` на refresh = сессия закончилась (отозвана, истекла или аккаунт удалён):

- у аккаунта есть email → экран «Сессия завершена», предложить [восстановление](#восстановление-аккаунта);
- анонимный аккаунт → доступа к нему больше нет. Создать новый анонимный, неотправленные локальные изменения отправить уже от нового аккаунта (узлы создадутся заново) и честно сообщить пользователю.

## Устройство и APNs-токен

```http
POST /v1/devices
{ "installation_id": "<UUID из Keychain>", "apns_token": "<hex>", "apns_environment": "sandbox", "app_version": "1.0.3" }
```

- `installation_id` — сгенерировать один раз и хранить в Keychain.
- `apns_environment`: `sandbox` для сборок из Xcode, `production` для TestFlight/App Store (определять по сборке/entitlement).
- Вызывать: после авторизации, при каждом новом токене из `didRegisterForRemoteNotificationsWithDeviceToken`, при смене версии приложения. Без токена (уведомления запрещены) — можно регистрировать без `apns_token`.
- Идемпотентно, `Idempotency-Key` не нужен; в Outbox не обязателен — достаточно повторять при старте.
- При выходе / удалении аккаунта — `DELETE /v1/devices/{installation_id}`.

## Профиль

```http
GET   /v1/me
PATCH /v1/me   { "display_name": "Аня" }      (Idempotency-Key, через Outbox)
```

`display_name` до 60 символов, пусто — сбросить. Имя видят связи и участники совместных узлов. Профиль также приходит в sync (`entity_type: user`).

`features` — доступные AI-функции, `ai_consent_at` — согласие на AI (`PUT /v1/me/ai-consent`). Что с ними делать — [07 → Доступ к AI-функциям и согласие](07-ai.md#доступ-к-ai-функциям-и-согласие).

## Часовой пояс

Отправлять текущий пояс устройства: при первом входе и при каждой смене. Сервер переводит узлы пользователя в новый пояс с тем же местным временем.

```http
PUT /v1/me/timezone   { "timezone": "America/New_York" }     (Idempotency-Key)
→ { "timezone": "…", "adapted_nodes": 12, "skipped_shared_nodes": 1, "skipped_past_nodes": 3 }
```

Как определять смену и порядок действий — [04 → Смена часового пояса](04-feed-occurrences-notifications.md#смена-часового-пояса).

## Привязка email

Экран в настройках «Сохранить аккаунт» / «Привязать email»:

1. `POST /v1/auth/email/start { email }` → `202` (ответ всегда одинаковый).
2. Ввод 6-значного кода → `POST /v1/auth/email/verify { email, code }` → профиль (`is_anonymous: false`). `UserId` и все данные остаются прежними.

| `code` | Показать |
|---|---|
| `invalid_code` | «Неверный или устаревший код» (после 5 ошибок код сгорает — запросить новый) |
| `email_already_linked` | «Этот email уже привязан к другому аккаунту — войдите через восстановление» |
| `validation_failed` | некорректный email |

Повторная отправка кода — не чаще раза в минуту (кнопка с таймером), не больше 5 в час.

## Восстановление аккаунта

Тихий пункт в настройках «Восстановить аккаунт» (в onboarding не предлагать). Сценарий — новое устройство или переустановка:

1. Предупредить: данные текущего анонимного аккаунта на этом устройстве не перенесутся.
2. `POST /v1/auth/email/sign-in/start { email }` → `202` (одинаково для любого email).
3. `POST /v1/auth/email/sign-in/verify { email, code }` → токены восстановленного аккаунта.
4. Заменить токены в Keychain, очистить локальную БД и Outbox старого аккаунта, `POST /v1/devices`, `GET /v1/sync/snapshot`.

## Выход

`POST /v1/auth/logout { refresh_token }` (сессия отзывается), `DELETE /v1/devices/{installation_id}`, очистить Keychain и локальную БД. Перед выходом анонимного аккаунта предупредить, что вернуться в него нельзя.

## Удаление аккаунта

Обязательно по правилам App Store. Настройки → «Удалить аккаунт» → подтверждение:

```http
DELETE /v1/me   → 204        (без Idempotency-Key, не через Outbox — только при наличии сети)
```

После `204` — очистить Keychain, локальную БД, Outbox, отменить все локальные уведомления. Повтор после потерянного ответа вернёт `401` — это тоже «аккаунт удалён». Совместные узлы пользователя у других участников исчезнут через их sync.

## Rate limits

`429 rate_limited`: `auth` — 20/мин с IP (anonymous, refresh, logout), `otp` — 10/мин с IP (email-коды, приглашения), `ai` — 10/мин на пользователя. Повторять с backoff.
