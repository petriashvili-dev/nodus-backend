# Push и deep links

Серверная сторона — [../05-realtime-and-push.md](../05-realtime-and-push.md).

APNs приходит только для внешних событий. Push — **сигнал**, не данные: после открытия всегда синхронизироваться; push может не прийти — всё, о чём он сообщает, видно и без него.

## Регистрация

- Разрешение на уведомления запрашивать в понятном контексте (при первом напоминании, при включении совместных узлов), отказ ничего не блокирует.
- Токен → `POST /v1/devices` ([01](01-auth-and-account.md#устройство-и-apns-токен)).

## Payload

```json
{
  "aps": { "alert": { "title": "Черновики готовы", "body": "Проверьте и подтвердите новые узлы." },
           "sound": "default", "thread-id": "ai_drafts_ready" },
  "nodus": { "kind": "ai_drafts_ready", "event_id": "ai-drafts-…", "job_id": "…" }
}
```

Тексты нейтральные: в push нет названий узлов и продиктованной речи.

## Маршрутизация

| `nodus.kind` | Поле | Экран по нажатию |
|---|---|---|
| `shared_node_changed` | `node_id` | узел (сначала sync, потом открыть) |
| `connection_changed` | `connection_id` | «Связи»; если `awaiting_my_confirmation` — карточка подтверждения |
| `ai_drafts_ready` | `job_id` | экран проверки AI-черновиков — **тот же**, что открывается из foreground ([07](07-ai.md)) |
| `import_ready` | `import_id` | экран проверки импорта ([08](08-export-import.md)) |
| неизвестный | — | открыть приложение, sync |

Порядок при нажатии: Delta Sync → дождаться появления сущности локально → открыть экран. Если сущности нет (удалена, доступ потерян) — открыть главный экран.

## Foreground

- `userNotificationCenter(_:willPresent:)`: для событий, которые пользователь и так увидит в открытом приложении (через SSE), не показывать системный баннер — показать фирменный toast. Полностью исключить двойной показ в гонке foreground/background нельзя.
- Новый совместный узел в активном приложении — мягкая анимация появления + toast.

## Дедупликация

Хранить `event_id` показанных in-app уведомлений/push (например, за 7 дней) и не показывать одно событие дважды. Для SSE-сигналов дедупликация не нужна: они только запускают sync.

## Background/terminated

Silent push не используются. Обработка — при открытии приложения по нажатию или при следующем запуске (обычный sync).
