# Узлы, экземпляры, лента и локальные уведомления

Серверная сторона — [../03-nodes-and-recurrence.md](../03-nodes-and-recurrence.md).

## Узел и экземпляр

`NodeDto` (из sync, `GET /v1/nodes/{id}`, ответов мутаций):

```json
{
  "id": "…", "type": "recurring", "owner_id": "…",
  "title": "Зарядка", "description": null, "timezone": "Europe/Moscow",
  "date": null, "time": null, "scheduled_at": null,
  "recurrence": { "frequency": "daily", "interval": 1, "start_date": "2026-10-01", "until": null,
                  "times": ["07:30"], "week_days": [], "month_day": null },
  "track_years": false, "revision": 2, "version": 5,
  "created_at": "…", "updated_at": "…",
  "members": [ { "user_id": "…", "display_name": "Аня" } ],
  "horizon": { "from": "2026-10-17", "to": "2026-12-02" },
  "occurrences": [ …OccurrenceDto… ]
}
```

`OccurrenceDto` — готовый экземпляр для карточки и уведомления:

```json
{ "node_id": "…", "key": "g0-20261018-0", "revision": 2, "title": "Зарядка", "description": null,
  "date": "2026-10-18", "time": "07:30", "scheduled_at": "2026-10-18T04:30:00+00:00",
  "years": null, "state": "tied", "completed_at": null, "is_past": false }
```

- `key` — стабильный идентификатор экземпляра (`g{поколение}-{yyyyMMdd}-{слот}`, у одноразовых — `once`). Все действия и уведомления привязывать к паре `node_id + key`.
- `title`/`time` экземпляра могут отличаться от текущего шаблона: прошлые экземпляры показываются **как были** (история правок). Не восстанавливать их по текущему названию/правилу.
- `time = null` — на весь день; `scheduled_at = null` у таких и у недатированных.
- `years` — у годовщин с `track_years`: сколько лет исполняется.
- `is_past` + `state: tied` — прошедший невыполненный: как показывать (просрочено/скрыть) — решение UI.

Типы при создании: `one_time` (`date?`, `time?`), `recurring` (`recurrence`, даты и время только в правиле), `anniversary` (`date` — исходная дата, `time?`, `track_years`). Полный контракт — [09](09-api-reference.md#узлы).

Правка (`PATCH`) отправляет **полный** шаблон + `expected_version`; тип узла не меняется.

## Лента (главный экран)

Источник — `GET /v1/feed?from=<сегодня-1>&to=<+365 дней>` (диапазон до 400 дней):

```json
{ "generated_at": "…", "from": "…", "to": "…",
  "items": [ { "node_type": "recurring", "node_version": 5, "occurrence": { …OccurrenceDto… } } ] }
```

Сервер уже применил правило: одноразовые в диапазоне и без даты; у регулярных и ежегодных — **сегодняшние экземпляры + ближайший следующий** (если сегодня нет — ближайший будущий, даже если он через полгода).

- Кешировать последний ответ локально; офлайн показывать кеш + локальные pending-изменения поверх.
- Перезапрашивать после каждого цикла sync, при смене дня и пояса.
- Разделы «Сегодня», «Завтра», месяцы — группировка на клиенте по `date` экземпляра.
- Недатированные (`date = null`) — отдельный раздел.

## Горизонт и локальные уведомления

Обычные напоминания планируются **локально** (`UNUserNotificationCenter`), APNs для них не используется.

Данные для планирования:

- `occurrences` в каждом `NodeDto` — окно от вчера до +45 дней (`horizon`);
- окно «стареет», если узел долго не меняется, поэтому раз в день (и при смене дня/пояса) обновлять всё окно:
  ```http
  GET /v1/occurrences?from=<сегодня-1>&to=<+45 дней>      (до 120 дней)
  → { "generated_at", "from", "to", "occurrences": [ …OccurrenceDto… ] }
  ```
  и заменить локальные экземпляры в этом окне целиком (недатированные одноразовые сюда не входят — они остаются из узла).

Правила планирования:

- идентификатор уведомления — `"\(node_id):\(key)"`; хранить соответствие для отмены/обновления;
- планировать только `state = tied`, не `is_past`, с `scheduled_at` (на весь день — в выбранное пользователем время, например 09:00 местного; это настройка клиента);
- лимит iOS — 64 ожидающих уведомления: брать ближайшие, при каждом sync/смене дня перепланировать скользящее окно;
- после развязывания экземпляра — отменить его уведомление сразу (локально), до ответа сервера;
- после sync — перепланировать только затронутые узлы.

## Смена дня

`UIApplication.significantTimeChangeNotification` (полночь, смена пояса, DST) и проверка даты при возврате в foreground → обновить ленту и окно экземпляров, перепланировать уведомления. Без сети — показывать кеш, помечать устаревшим, если ему больше суток.

## Смена часового пояса

Узлы пользователя переводятся в новый пояс **с сохранением местного времени** («09:00» остаётся 09:00 уже по новому поясу). Пересчёт делает сервер.

Определение:

- `NSSystemTimeZoneDidChange`;
- `UIApplication.significantTimeChangeNotification`;
- на старте и возврате в foreground — сравнить `TimeZone.current.identifier` с последним отправленным.

Порядок:

1. Отправить pending Outbox (адаптация увеличивает версии узлов — поздняя правка со старым `expected_version` получит `409`).
2. `PUT /v1/me/timezone { "timezone": "<IANA>" }` с `Idempotency-Key` (без сети — в Outbox; до выполнения показывать прежнюю проекцию).
3. Delta Sync → обновить ленту и окно экземпляров → перепланировать уведомления.

Не переводятся: прошедшие одноразовые узлы и **совместные** узлы (их время общее для участников). Если в ответе `skipped_shared_nodes > 0`, можно ненавязчиво показать, что совместные узлы остались во времени другого пояса. Новые узлы создавать в текущем поясе устройства.

## Узел создан без сети

Серверных экземпляров до первой синхронизации нет. Показывать **только ближайший** экземпляр из упрощённого локального расчёта:

- одноразовый — по своей дате/времени;
- регулярный — ближайшая подходящая дата правила;
- ежегодный — та же дата в этом или следующем году (29.02 → 28.02 в невисокосный).

Ключ этого экземпляра клиент вычисляет сам: у нового узла поколение всегда 0, поэтому `key = "g0-" + yyyyMMdd + "-" + slot` (slot — позиция времени в `times`, 0 если одно время или весь день); у одноразового — `once`. Офлайн-развязывание с таким ключом после sync попадёт в нужный экземпляр. После sync локальный расчёт заменяется серверными `occurrences`.

## Развязать / перевязать

- `PUT /v1/nodes/{id}/occurrences/{key}/untie { "completed_at": "…" }` / `…/retie` — через Outbox, UI обновляется сразу.
- Действует только на выбранный экземпляр.
- Ответ — состояние экземпляра; повтор того же действия безопасен.
- `404 occurrence_not_found` — экземпляра больше нет (правило изменилось): откатить локально, sync.
- После развязывания одноразового узла — возможно, показать [продолжение](07-ai.md#продолжение-нити).

## История узла

`GET /v1/nodes/{id}/occurrences?from&to` (до 400 дней) — прошлые и будущие экземпляры с историческими названиями и состояниями. Пагинировать по диапазонам дат.
