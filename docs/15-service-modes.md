# Серверные режимы сервисов

`ServiceMode` — отдельная серверная секция настроек. Сейчас реализован переключатель Email: `Live` / `Mock`. Это аналог почтового service_mode Eatee: режим управляет выдачей кода и вызовом транспорта. Переключателей без реализации для LLM, SMS или других сервисов нет.

Настройки задаются через Environment/secrets Dokploy, не через публичную команду `config`. Они применяются после пересоздания backend-контейнера; изменения без перезапуска и хранение режимов в БД не добавлены. В `GET /v1/app-config`, sync и ответах авторизации режим и MockCode не выдаются.

## Временно работать без SMTP

```dotenv
ServiceMode__Email=Mock
EmailOtp__MockCode=<ваш-секретный-код-из-6-цифр>
EmailOptions__Smtp__Host=
```

Значение MockCode нужно заменить шестью ASCII-цифрами; заполнителя недостаточно. Секрет задаётся только на сервере, не коммитится. SMTP host, пароль и подключение к сети Eatee в этом режиме не нужны. Backend запускается в Production без SMTP, MailKit-клиент не регистрируется; уже заполненные SMTP-настройки не приводят к отправке.

На клиенте выполняется обычный поток: запросить код → ввести MockCode → подтвердить email либо войти в существующий аккаунт. Участвуют те же эндпоинты, что в Live. Сам код не возвращается API и не пишется в логи.

- Код требуется сначала запросить; универсального обхода проверки нет.
- Сохраняется только HMAC-хеш с текущим pepper, как для обычного OTP.
- Привязка ограничена запрашивающим UserId; код привязки нельзя использовать для входа.
- Сохраняются срок действия, cooldown, часовой лимит, число попыток и одноразовость.
- Запрос входа на неизвестный email отвечает как прежде, но не создаёт аккаунт и код.
- Для адресов App Review приоритет сохраняет отдельный ReviewCode.

Mock позволяет подтверждать адреса общим известным оператору кодом и не доказывает владение почтовым ящиком. Он включается только явной серверной настройкой; по умолчанию всегда Live.

## Включить настоящую отправку

```dotenv
ServiceMode__Email=Live
```

Настроить SMTP по [14-smtp.md](14-smtp.md) и пересоздать backend. В Production Live требует Host; неверные настройки транспорта останавливают запуск. Код снова генерируется случайно, наличие EmailOtp__MockCode само по себе его не включает. MockCode можно удалить из Environment.

Переключение меняет выдачу новых кодов. Уже выданные коды любого режима остаются одноразовыми и действуют до обычного срока истечения; перезапуск не удаляет их из БД. Миграции схемы и изменения iOS не требуются.

## Временно работать без APNs

```dotenv
Apns__Enabled=false
```

По умолчанию push выключены. Ключи Apple можно оставить пустыми. После пересоздания API не создаются новые push-события/задания, ранее поставленные завершаются без доставки; накопления для последующей отправки нет. Локальные напоминания iOS, SSE и синхронизация сохраняются. Для включения заполнить ключи Apple и задать `Apns__Enabled=true`. Подробнее — [05-realtime-and-push.md](05-realtime-and-push.md).

## Настройки Email и реализация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ServiceMode__Email` | `Live` | `Live` — реальный транспорт, `Mock` — фиксированный код без почты |
| `EmailOtp__MockCode` | пусто | серверный секрет; ровно 6 ASCII-цифр, обязателен при Mock |

Неизвестный режим, числовое значение вне enum, пустой или неверный код при Mock не допускаются при запуске. Отправитель и настройки остальных сервисов сохраняют свои правила.

Код: `Infrastructure/ServiceModes/ServiceModeOptions.cs`, `Infrastructure/Email/EmailTransportSetup.cs`, `Authentication/EmailOtpService.cs`. Проверки: `ServiceModeOptionsTests`, `MockEmailTests`, `LiveEmailModeTests`, прежние `ReviewAccountTests` и SMTP-тесты.

Историческая проверка Email до добавления выключателя APNs: 207 тестов backend прошли, в том числе запуск приложения с Production-конфигурацией без SMTP host и подтверждение Mock-кодом. Сборка без ошибок и новых предупреждений компилятора; прежние предупреждения NuGet по OpenTelemetry сохраняются.

Выключатель APNs добавлен без запуска сборки и тестов по просьбе пользователя.
