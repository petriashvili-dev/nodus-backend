# Планы и доступ к функциям

Код: `Plans/`. Решение и рассмотренные варианты — [ADR 0001](adr/0001-user-plans-and-features.md).

У пользователя есть **план**: обычный (`Standard`) или **Nodus+** (`Plus`). План определяет набор **функций**: сейчас это все AI-функции. Nodus+ выдаётся вручную и бесплатно группе тестирования; клиенту отдаётся только список доступных функций, о плане и подписке приложение ничего не показывает. Кроме плана, для AI-функций нужно **согласие пользователя** на передачу данных AI-провайдеру.

## Функции

| Ключ | Функция | Где проверяется | Без доступа |
|---|---|---|---|
| `ai_drafts` | [голосовой разбор в черновики](07-ai-drafts.md) | `FeatureFilter` на `POST /v1/ai/node-drafts`, **до** идемпотентности | `403`, ключ идемпотентности не сохраняется |
| `ai_continuations` | [«Продолжение нити»](08-ai-continuations.md) | `ContinuationTrigger` перед записью outbox-события и ещё раз в `ContinuationRunner` после debounce | молча: конвейер не запускается, текст узла модели не уходит |
| `ai_import` | [AI-импорт чужого файла](10-export-import.md#чужой-файл-через-ai-и-подтверждение) | `ImportService.QueueAiImportAsync` — только ветка AI | `403`; файл Nodus импортируется у всех |

Что **не** закрывается: чтение, подтверждение и отмена уже созданных заданий черновиков и импорта, показ и принятие готовых предложений. Модель там не вызывается, а пользователь не теряет результат, если доступ пропал. Задание, принятое до потери доступа, обрабатывается до конца.

## Данные

Колонки `users`:

| Колонка | Смысл |
|---|---|
| `plan` | `Standard` \| `Plus` (`ck_users_plan`); новые пользователи — `Standard` |
| `plan_source` | `Manual` для выданного вручную, `null` для `Standard` |
| `plan_expires_at` | момент окончания; `null` — бессрочно |
| `ai_consent_at` | момент согласия на AI; `null` — не соглашался или отозвал |

**Действующий план** — `Plus`, пока `plan_expires_at` не наступил, иначе `Standard`. Считается при каждом чтении через `TimeProvider`; отдельной задачи «истечения» нет.

## План → функции

Набор функций каждого плана — в конфигурации `Plans:<План>:Features`. Если ключ не задан, по умолчанию у `Plus` все функции, у `Standard` — ни одной. Заданный список **заменяет** умолчание. Неизвестный ключ функции — ошибка при старте (`ValidateOnStart`).

```json
"Plans": {
  "Standard": { "Features": [] },
  "Plus": { "Features": [ "ai_drafts", "ai_continuations", "ai_import" ] }
}
```

Открыть функцию всем — добавить её в `Standard` (через переменную окружения `Plans__Standard__Features__0=ai_import`), без релиза кода.

## Проверка (`FeatureAccess`)

```
функция в плане? ── нет ──→ 403 feature_not_available
      │ да
AI-функция и нет согласия? ── да ──→ 403 ai_consent_required
      │ нет
   разрешено
```

План проверяется первым: пользователю без плана не нужно предлагать согласие. Результат кешируется на запрос или фоновую задачу (scoped), поэтому пакетное создание узлов не читает пользователя на каждый узел.

```json
{ "type": "https://nodus.app/problems/feature_not_available", "title": "Feature is not available.", "status": 403,
  "code": "feature_not_available", "feature": "ai_drafts" }
```

Для `ai_import` проверка выполняется внутри идемпотентного обработчика, поэтому отказ сохраняется за ключом (как `ai_quota_exceeded`): клиент не повторяет операцию, а создаёт новую с новым ключом.

## Профиль клиента

`UserProfile` (`GET /v1/me`, сущность `user` в sync и snapshot, ответы `PATCH /me`, `PUT /me/ai-consent`, `email/verify`):

```json
{ "id": "…", "features": ["ai_continuations", "ai_drafts", "ai_import"], "ai_consent_at": "2026-10-18T09:00:00Z", … }
```

`features` — функции действующего плана **без учёта согласия**, отсортированы. Выдача и отзыв плана, согласие и отзыв согласия увеличивают `users.version` и пишут `user` в журнал sync — устройства получают изменение через sync/SSE. Истечение срока плана изменения в sync не создаёт: клиент увидит новый список при следующем `GET /me` или после `403 feature_not_available`.

## Согласие на AI

```http
PUT /v1/me/ai-consent      (Idempotency-Key)
{ "granted": true }
→ 200 UserProfile
```

- `granted: true` ставит `ai_consent_at`; повтор не меняет ни момент первого согласия, ни `version`.
- `granted: false` обнуляет `ai_consent_at`. «Продолжение нити», уже ожидающее debounce, после отзыва не вызовет модель.
- Без `granted` → `400 validation_failed`.
- Узлы, созданные до согласия, задним числом в конвейер не отправляются.

## Выдача плана

HTTP-эндпоинта нет: план меняет оператор командой приложения (как `migrate`).

```bash
dotnet run --project Nodus.Api -- plan set --email user@example.com --plan plus
dotnet run --project Nodus.Api -- plan set --user-id <uuid> --plan plus --expires 2027-01-01T00:00:00Z
dotnet run --project Nodus.Api -- plan set --email user@example.com --plan standard
dotnet run --project Nodus.Api -- plan list

docker compose run --rm nodus-api plan set --email user@example.com --plan plus   # на сервере
```

| Код выхода | Значение |
|---|---|
| `0` | план изменён или уже такой |
| `1` | пользователь не найден |
| `2` | неверные аргументы (справка выводится в консоль) |

- Ровно один из `--email` / `--user-id`. `--expires` — только для `plus` и только в будущем.
- Изменение идёт через `UnitOfWork` с записью в журнал sync; outbox-событие доставит его запущенный API (опрос `Outbox:PollSeconds`).
- В лог пишутся только `user_id`, план и срок. `plan list` выводит в консоль id, email, план, срок и наличие согласия у пользователей с не-`Standard` планом, включая истёкшие.
- Выдавать стоит аккаунтам с привязанным email: анонимный аккаунт теряется при переустановке.

## Метрики

`nodus_feature_denied_total{feature, reason}` — отказы по явным запросам (`reason`: `not_in_plan`, `consent_required`). Молчаливые отказы «Продолжения нити» не считаются.

## App Store

Сейчас Nodus+ бесплатный и выдаётся вручную, оплаты нет ни в приложении, ни вне его. Для ревью в App Review Notes указывается, что AI-функции включены на сервере для ограниченной группы, и даётся демо-аккаунт с Nodus+. Если Nodus+ станет платным — только через In-App Purchase: появится источник `AppStore`, а проверки и поле `features` не изменятся. Ревьюер входит в демо-аккаунт по email с фиксированным кодом — [02 → Демо-аккаунт для App Review](02-authentication.md#демо-аккаунт-для-app-review).
